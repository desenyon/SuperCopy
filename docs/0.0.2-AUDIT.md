# 0.0.2 clipboard audit

## Granola finding

The user confirmed ordinary paste works but SuperCopy misses the dictation in history. A metadata-only inspection of the supplied sample found `org.nspasteboard.TransientType` alongside plain text, HTML, and Chromium provenance formats. No clipboard text was read or logged during that inspection. The installed Granola build was 7.786.3.

SuperCopy 0.0.1 deliberately rejects all transient content. Granola's sample did not contain a reliable Granola-origin marker, so automatically allowing all transient content whenever Granola is running would also capture unrelated temporary/private copies. The scoped fix is an explicit **Save temporary text** preference, off by default. It accepts known text/HTML/RTF formats, still rejects concealed/password markers and temporary non-text payloads, and retries the current clipboard when changed. It applies to other apps' qualifying temporary text as well.

## Reproduced and fixed for 0.0.2

| Finding | Evidence and fix |
| --- | --- |
| Dictation marked temporary is skipped | Sample's format markers confirmed the policy mismatch. An opt-in unit fixture saves the same text/HTML/Transient combination; the default still rejects it. |
| All autogenerated text is dropped | Named-pasteboard regression failed on 0.0.1. Non-sensitive generated text is now accepted; SuperCopy marks its own replays separately. |
| Lazy text at an existing revision is lost | Declare text, let the monitor observe missing bytes, then supply text without changing `changeCount`. The monitor now retries. |
| Marker-only data is mistaken for content | Publish ready autogenerated/source/temporary markers before text. The old code saved a marker entry and acknowledged the revision. Readiness now requires a non-empty real payload; a ready temporary marker or empty text placeholder cannot complete capture. |
| Empty-then-filled revisions are lost | Clear the pasteboard, wait, then set text at the same `changeCount`. Empty revisions are retried, without an error for genuinely empty clipboards. |
| Failed saves are never retried | Replace the fixture's storage directory with a file, observe a save error, repair storage, and verify capture of the unchanged clipboard. |
| Monitor cannot restart | `stop()` set a flag that `start()` never cleared. A stop/start regression now captures the next copy. |
| Concealed text can appear in picker summaries | Concealed plus autogenerated markers bypassed the old preview guard. Concealed/password markers now always take precedence, including when temporary-text capture is enabled. |
| Self-tests depend on real capture preferences | Named test suites now isolate pause/exclusion/temporary-text settings from the installed app. |

Core and app tests use temporary history and named pasteboards. Event delivery is recorded, not injected into external apps. No dictation was created by desktop automation.

## Other candidates to evaluate

- **Source-aware exclusions:** source metadata and exclusions still use the frontmost app. Background dictation can be attributed to the destination. Prefer a trustworthy source hint when present, with a clear fallback. This is a confirmed design limitation; the Granola sample had no usable source-app marker.
- **Additional text extraction:** `ContentAnalysis` extracts UTF-8, UTF-16 external, RTF and URLs, but does not extract HTML-only or UTF-16 native text for search. Original bytes are preserved. Add fixtures before expanding decoding.
- **Rapid temporary copies:** polling every 350 ms can miss content overwritten between polls. Faster/adaptive capture needs energy profiling and still cannot guarantee every intermediate value.
- **Foreign synthetic shortcuts:** the event tap currently identifies its own synthetic events but does not classify other apps' injected paste events. Validate dictation/automation interoperability live before changing interception.
- **Longer provider/storage recovery:** the retry budget is eight attempts (roughly 2.5 seconds plus read/save work). Recovery after exhaustion requires another copy or an explicit policy-triggered retry. A user-visible Retry action is a possible follow-up.

These are candidates, not claims of completed fixes. Intel/older-macOS runtime, quarantined-download Gatekeeper acceptance, and live target-app paste coverage remain release checks.
